# diskstack progress

Version 1.0.0, feature complete. Nothing is in flight.

## State

Everything in the v1 brief is built and running:

* `diskstack/cli.py` - click entry point, every flag documented in `--help`.
* `diskstack/candidates.py` - one `Candidate` per sector per revolution per
  input, for SCP flux and for `.img` / `.ima` / `.st` / `.adf` / `.imd`.
* `diskstack/stack.py` - the three tiers: CRC-clean, recovered by byte-wise
  vote, unresolved.
* `diskstack/filler.py` - Greaseweazle's `-=[BAD SECTOR]=-` counted as a
  failed read, not as data.
* `diskstack/formats.py` - format detection, image open and image write.
* `diskstack/report.py` - JSON report, the stdout tables, the `gw read
  --tracks=` command.
* `diskstack/parallel.py` - the same decode as `candidates.flux_candidates`,
  one track per worker process, collected in track order.
* `diskstack/_vendor/greaseweazle` - 100 files regenerated by `tools/vendor.py`
  from commit 26690f8. Every local change is listed in `NOTICE`.

## Verified working

Run on this machine, not inferred:

* `python -m pytest tests -q` - 61 passed in 19s. The suite builds real SCP
  flux from a real PC floppy image and decodes it back.
* Three damaged captures stacked into a file byte-identical to the source
  `Transylvania.img` (368640 bytes). Two captures leave exactly 6 unresolved
  sectors on cylinders 17-19 head 0 and print
  `gw read retry.scp --tracks=c=17-19:h=0`, exit code 2.
* The printed trackspec round-trips through Greaseweazle's own `TrackSet`
  parser, so it is valid syntax rather than something that merely looks right.
* AmigaDOS flux encoded, damaged and voted back; two `.adf` images merged
  through the CLI.
* Parallel decode gives byte-identical candidates and identical per-file
  tallies to the serial path, checked capture by capture. One capture: serial
  8.49s, parallel 1.18s, 2058 candidates either way. The three-capture CLI
  merge went from 32s to 6.2s and still wrote the byte-identical image.
* Wheel and sdist build, install into a clean venv, and
  `uvx --from ./dist/diskstack-1.0.0-py3-none-any.whl diskstack --version`
  works.
* `pyflakes diskstack tests tools` is clean outside `_vendor`.
* Clone check (difflib over function bodies): highest pair in the product code
  is 0.48 and is a closure counted against its own enclosing function.

## Next step

Publish. `python -m build` then `twine upload dist/*`. The PyPI name
`diskstack` was free when this was written. After that, the one distribution
step worth doing is a post in the Greaseweazle discussion forum or
`r/datarecovery` describing the re-read loop, because the people who already
own a flux reader are the only people who can have two dumps of one disk.

Ask for `diskstack-report.json` from a real deteriorated disk. The damage in
the test fixtures is synthetic and that is the one honest weakness in the
validation story.

## Not built, in rough order of value

* **A decoded-candidate cache.** Re-running with one more capture re-decodes
  the captures that have not changed. A `.diskstack-cache` keyed on file hash
  plus PLL settings would make the loop feel instant.
* **More input formats.** KryoFlux `.raw` streams, HxC `.hfe`, Applesauce
  `.a2r`. All are flux containers Greaseweazle already reads, so the work is
  format detection and geometry, not decoding.
* **GCR.** Apple II and Commodore. Explicitly out of scope for v1, and the
  vote needs a per-sector checksum, which GCR formats do have.
* **Flux output.** Writing a merged `.scp` rather than a sector image. This is
  the only way to preserve copy protection, and it is a different algorithm:
  you cannot vote on flux intervals, you have to pick whole revolutions.
  Unstable sectors are detected and reported now, but a sector image cannot
  hold them, so this is the only real fix.
* **Per-format geometry check on sector images.** A wrong-sized `.img` warns.
  A right-sized image of a different disk still merges silently, and nothing
  short of reading the filesystem would catch that.
